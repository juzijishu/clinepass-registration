# 已有订阅的续订管理与入池

## 操作

1. 在 Auto 中保存账号通过正常登录取得的授权会话。仅导入邮箱密码不会获得该会话。
2. 在设置的「订阅与入池」标签填写目标 clinebypass 根地址、独立管理员密码、客户端密钥归属 ID，例如 `legacy`。已有密码以掩码返回，留空保存保留原密码。目标地址以 Auto 所在服务器为准；远程地址必须 HTTPS，本机回环地址允许 HTTP。
3. 在批次详情的单账号菜单选择「关闭续订并入池」，阅读并确认操作范围。
4. 在运行记录查看校验会话、关闭续订、保存 Key、入池及回读阶段。只有回读到相同 Key 和客户端归属才完成。

此任务复用现有队列和账号互斥，允许已有付费账号运行，固定关闭自动支付，不启动浏览器登录、注册或接码。会话必须由官方 `/api/v1/users/me` 返回的邮箱和用户 ID 验证，不从 Cookie 文本或网页猜测身份。

## 执行与恢复

- 官方订阅查询必须有当前有效权益及明确的周期结束时间。关闭续订后要求订阅 ID、周期结束时间不变，且 `cancelAt` 等于当前周期结束时间。若已经满足条件，跳过重复取消。
- 创建 Key 前在 Auto 数据库 `subscription_checkpoints` 中持久化 `key_pending`；取得 Key 后在同一事务内保存断点 `key_saved` 以及账号 Key 和用户 ID。旧会话、邮箱凭据和其他账号字段保留。
- 入池失败时，在同一菜单重试。任务重新校验会话和续订状态，复用持久化的 Key；不会再次创建。
- `key_pending` 表示 Key 创建或本地保存结果不确定，重试仍会停止。请在官方后台核对、必要时撤销不确定的 Key，再由维护人员依据官方结果处理断点。系统不提供无条件重置按钮。
- 号池登录需非 pending 管理会话、Cookie、Origin 和 CSRF；操作结束尝试注销临时管理会话。全程直连且拒绝重定向。
- 目标 `/api/accounts` 是整表替换：读取完整账号快照和调度配置、携带 `expectedConfigurationRevision` 保存。原账号 ID 与全部字段保留；新 ID 由目标生成。冲突或响应丢失后先重读，最多尝试三次。已存在的 Key 归属不同、稳定名称冲突或快照字段缺失时停止。

## 验证范围

自动化测试使用临时数据库及本地模拟官方、号池接口，不使用真实订阅、管理员凭据或付费上游。额外可用当前 clinebypass 源码运行隔离契约测试：

```sh
CLINEBYPASS_TEST_SOURCE=/absolute/path/to/clinebypass go test ./internal/clinebypass -run TestAppendAgainstIsolatedClinebypass -count=1
```

该测试单独创建临时 DATA_DIR、合成密码和账号，启动独立 Node 进程，验证真实管理员认证、保存、字段保留、服务端 ID 生成及幂等。官方响应契约仍需要在实际已授权订阅上验收；模拟成功不代表真实订阅取消已经完成。

管理员密码、授权会话和 Key 是本地私密数据库内容，数据库及备份按凭据文件保护。任务日志只记录固定状态与脱敏错误，不记录官方响应体、Cookie 或 Key。
