# 注册流程

从批量导入的身份账号到可用号池的完整链路。适用于 Google 与 Microsoft 两类账号，
由 Auto 服务执行，主程序只负责下发任务与汇总状态。

## 流程总览

一批账号进入后，每个账号独立走完五个阶段，互不阻塞：

| 阶段 | 标签 | 位置 | 内容 |
| --- | --- | --- | --- |
| `queued` | 等待执行 | Auto 调度器 | 排队等待并发槽位 |
| `browser` | 启动浏览器 | worker | 按设置启动 Chromium 与分阶段网络 |
| `login` | 账号登录 | worker | 打开邀请链接、走 Google/Microsoft 登录、进入 Cline |
| `verification` | 安全验证 | worker | AuthKit Radar 手机验证（自动接码或人工接码） |
| `payment` | 提取与支付 | worker | 抓取 Stripe 支付链接、保存 Cookie |
| `saving` | 保存结果 | 主程序 | 回写账号状态与凭据 |
| `done` | 已完成 | 主程序 | 批次内该账号收尾 |

登录成功后若开启「订阅与入池」，追加三个后处理阶段：

| 阶段 | 标签 | 内容 |
| --- | --- | --- |
| `subscription` | 校验订阅会话 | 用已保存会话确认身份，与邮箱比对 |
| `renewal` | 关闭续订并复查 | 关闭到期自动续订，复查当前权益仍有效 |
| `key` | 创建并保存 Key | 创建 API Key（含断点记录，避免重复创建） |
| `import` | 入池并回读 | 追加到目标号池并回读确认 |

全部账号进入成功、失败或待人工处理状态后批次结束。**失败不冒充成功** —— 任何
阶段无法确认结果时停止并标记，不猜测、不自动重试破坏性操作。

## 登录阶段

worker 打开邀请链接（默认 `https://authkit.cline.bot`），按账号的 `login_provider`
分流：

- **Google**：识别账号选择器、密码页、服务条款页、同意授权页、`unknownerror` 页，
  逐步推进并对卡住页面做恢复（滚动到底、重试点击）。
- **Microsoft**：走 `login.live.com` / `login.microsoftonline.com` 授权流程。

两个分支最终都汇入「等待进入 Cline」循环：轮询页面地址，直到进入
`app.cline.bot` 或 Radar 验证页。期间自动处理服务条款与同意授权，超时抛
`authkit_stuck`。

到达 dashboard 后序列化 Cookie，并尝试抓取 Stripe 支付链接。

## 验证阶段

AuthKit Radar 要求手机验证。两种模式二选一：

### 自动接码

调用 HeroSMS 取号、等短信、回填验证码。约束：

- 区域只允许官方目录中的 `16`（英格兰），管理 API 拒绝保存其他非零区域，
  Python 执行器取号前再校验一次。
- 单号限价、每账号预算、每批次预算、取号次数、等待时长均可配置。
- **预算未配置时不执行收费取号**；启用流程且未开人工接码时，必须配好预算。
- 取号发生不明确超时时停止并核查，不盲目重发。
- 号码用尽或超时可换号重试，默认 3 次（可设 1–20）。

### 人工接码

「订阅与入池」中开启后，流程停在手机号输入页：

- 不取号、不填号，不消耗取号次数与预算，也不需要 HeroSMS 密钥、区域或限价。
- 浏览器、Cookie 与分阶段网络**保持原样**，不关页面也不重建连接。
- 检测到离开验证地址即继续，**其他标签页完成也算**（任一标签页进入 Cline 即视为完成）。
- 默认等待 1800 秒（可设 60–7200）。超时或浏览器被关闭按失败收尾，需重新排队。
- **必须有可见浏览器窗口**：本机或 VNC / 远程桌面操作。Linux 服务器上只有 Xvfb
  虚拟屏幕时窗口不可见，日志会警告，这种情况请改回自动接码。

## 分阶段网络

登录注册的流量按目标分流，详见 [分阶段网络](network-stages.md)：

| 目标 | 线路 |
| --- | --- |
| `authkit.cline.bot`、`app.cline.bot`、`api.cline.bot`、`.cline.bot`、`.workos.com` | 直连 |
| 微软、Google 登录及其余注册页面 | 设置中的浏览器代理 |
| HeroSMS 取号、轮询、结束与取消 | 独立中继，始终走代理 |

分流由中继按目标域名判断，**不做全局切换** —— 切换会关闭所有活动连接，把正在
进行的页面加载或 OAuth 回调掐断（表现为空白页或回调失败）。

浏览器保留同一个上下文与 Cookie。短信验证期间锁定其他标签页（验证页自身的
提交请求始终放行），退出验证后恢复。WebSocket 保持可用：Cline/Radar 可能依赖
它上报行为信号（鼠标轨迹、打字节奏），关闭会让风控按高风险处理。

代理缺失或连接失败时停止，不回退直连。

## 订阅与入池

登录成功后的后处理，与登录任务相互独立：

1. **校验身份** —— 用保存的会话确认 userID，与账号邮箱比对，不一致立即停止。
2. **关闭续订** —— 关闭到期自动续订并复查。**取消的是到期续订，保留当前有效权益**；
   没有有效套餐、取关不成功或状态不明确时不建 Key、不入池。
3. **创建 Key** —— 创建前先写 `key_pending` 断点。若上次创建结果不明，要求去官方
   后台人工核对，**不会自动重复创建**。
4. **入池** —— 追加到目标号池（HTTPS，本机回环可用 HTTP）并回读确认。

各阶段可重试，已成功的事实会保留，避免重复创建 Key 或重复导入。

## 浏览器选择

（2026-10-26 实测）Cline 侧 AuthKit Radar 能识别 cloakbrowser 的指纹特征，登录
完成后 OAuth 回调固定返回 `error=policy_denied`，与出口 IP、账号、线路、交互
流程均无关 —— 已用四个维度交叉验证：

| 变量 | 测试范围 | 结果 |
| --- | --- | --- |
| 出口 IP | 香港/韩国/台湾机房节点 + 家庭宽带真实 IP | 全部 `policy_denied` |
| 浏览器指纹 | cloakbrowser 指纹伪装开/关 | 全部 `policy_denied` |
| 浏览器 profile | 持久化 / 完全全新 | 全部 `policy_denied` |
| 账号 | 5 个以上不同账号 | 全部 `policy_denied` |
| 交互流程 | 各阶段人工式点击、同意授权页点「接受」 | 全部 `policy_denied` |

对照实验：**标准 Playwright Chromium + 无 route 拦截**可完整通过并到达取号环节。
因此默认浏览器已切换为标准 Chromium；需要指纹伪装的场景可设
`AUTO_CLOAK_BROWSER=1` 切回 cloakbrowser。

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 显式开启注册流程，旧登录/支付/续 Cookie 行为保持兼容 |
| `manual_sms` | `false` | 人工接码，不消耗预算 |
| `sms_max_attempts` | `3` | 取号次数，1–20 |
| `sms_wait_seconds` | `120` | 等短信时长，30–600 秒 |
| `manual_wait_seconds` | `1800` | 人工接码等待，60–7200 秒 |
| `sms_account_budget` | `0` | 每账号预算，0–10000 |
| `sms_batch_budget` | `0` | 每批次预算，0–10000 |
| `target_url` | — | 号池地址，须 HTTPS（本机回环可 HTTP），不含凭据/路径/查询 |
| `target_admin_password` | — | 号池管理员密码 |
| `target_client_key_id` | — | 客户端密钥归属 |

启用流程前必须配好号池三项；未开人工接码时还必须配好预算。

## 账号导入格式

- **Google**：`邮箱----密码----辅助邮箱`
- **Microsoft**：`邮箱----密码`,或六列 `邮箱----密码----Client ID----Refresh Token----辅助邮箱----附加字段`

六个字段的文件自动识别为微软。第 3/4 列已抽验能换取微软访问令牌，IMAP 尚未通过。
第六列用途未实证，仅保留。

导入支持 UTF-8 TXT 或粘贴文本，先预览再确认，上限 1 MiB / 1000 个账号。预览只显示
脱敏邮箱、登录方式、行号和校验结果，**不返回密码或 Token**。重复邮箱（忽略大小写）
跳过并保留已有凭据。详见 [邮箱导入说明](account-import.md)。

## 安全约束

- 原始敏感字段不进入普通日志或列表响应。
- 真实账号及代理订阅不入源码、测试、计划或提交。
- 本地启动使用独立 `DATA_DIR`、回环监听和私密日志。
- 入池使用管理员认证与 CSRF，不绕过目标服务认证。
- 使用实际页面/静态客户端证据确定订阅接口，不猜测端点后发起真实变更。
