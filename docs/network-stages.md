# 登录注册的分阶段网络

默认 Python 登录执行器使用以下固定规则：

| 阶段 | 网络 |
| --- | --- |
| 微软、Google 登录和其他注册页面 | 设置中的 Auto 浏览器代理 |
| `authkit.cline.bot` 的短信验证页面及该页面的资源、验证码提交 | 直连 |
| HeroSMS 取号、轮询、结束和取消号码 | 独立中继，始终使用设置中的代理 |
| 已有订阅的“关闭续订并入池”任务 | 直连，不启动登录浏览器 |

登录代理必须是可访问的 HTTP、HTTPS 或 SOCKS5 地址。订阅下载链接需要先交给本地代理客户端解析，不能直接填入代理框。代理连接失败时停止，不回退到直连。

浏览器保留同一个上下文及 Cookie；页面导航发出前切换中继网络，并关闭旧连接，避免复用上一阶段的 TLS 隧道。短信验证期间其他标签页的请求被阻止，退出验证后恢复；Service Worker、WebSocket 和 QUIC 不参与此登录流程。系统代理开关不需要随网页切换。应用层直连不等于绕过操作系统 VPN/TUN 路由，使用全局隧道时仍需核实系统路由。

## 人工接码

「订阅与入池」中开启人工接码后，流程在到达手机号输入页时停下，不调用 HeroSMS：不取号、不填号、不消耗取号次数与预算，只等手动填手机号、点发送并填验证码。等待期间浏览器、Cookie 与上表的分阶段网络全部保持原样，不关闭页面也不重建连接；检测到离开验证地址（含在其他标签页完成）后自动继续提取支付链接、建 Key 与入池。

人工接码必须有可见的浏览器窗口：登录动作强制按有界面方式启动，需要在本机或通过 VNC / 远程桌面操作。Linux 服务器上只有 Xvfb 虚拟屏幕时窗口不可见，日志会给出警告，这种情况请改回自动接码。等待时长默认 1800 秒，可设置 60–7200 秒；超时或浏览器被关闭按失败收尾，需要重新排队。保持分阶段网络依赖中继，因此人工接码同样要求配置浏览器代理：代理缺失或连接失败时不会回退到直连。

HeroSMS 区域仅允许目录中的 `16`（英格兰）。管理 API 拒绝保存其他非零区域；Python 执行器取号前再次验证。`0` 表示尚未配置，不能取号。号码价格仍取自接码设置，不因网络切换而改动。人工接码不涉及这些取号限制。

该规则作用于默认 Python 登录执行器，旧 Go 登录执行器不支持此分阶段切换。既有订阅的后处理是独立任务，不等于登录任务已自动完成续订取消或入池。

## 本地验证

普通 Go 与 Python 测试使用本地 HTTP、代理及合成数据，不访问真实登录、短信或支付服务。真实 Chromium 的可选验收验证同一会话中的登录、短信 GET/POST、退出页面的网络路径与 Cookie 保留：

```sh
STAGE_BROWSER_PYTHON=/path/to/python \
STAGE_BROWSER_EXECUTABLE=/path/to/chromium \
go test ./auto/internal/browser -run TestStageProxyWithRealBrowser -count=1 -v
```

不提供 `STAGE_BROWSER_PYTHON` 时此项跳过。省略可执行文件路径时使用该 Python 环境的 Playwright 默认浏览器，需要预先安装。
